clinicaltrialvghtpe v4.2.5 收案狀態修補報告

目的：修正「只顯示仍能收案」與收案狀態判斷過度自動化造成的誤判。

主要原因：
1. 舊版 isTrialNumericallyFull() 會從 targetNum / enrolled 任意抓第一個數字；targetNum = 3-5 且 enrolled = 3 時會被誤判成 enrolled >= target。
2. trialHasOpenEnrollment() 會因上述數字推論直接排除試驗，即使 status 已手動設為「進行中」。
3. targetNum / enrolled 在編輯與 Firestore 儲存時被 parseInt / Number 化，會破壞「3-5」、「0/2 (Prescreen)」、「需與 sponsor 要名額」這類臨床實用文字。
4. 沒有正式 status 欄時，從整列文字偵測到「停止/結束/滿額」可能覆蓋既有開放狀態。

本版修正：
1. 加入明確 open/closed status keyword 分流。
2. 手動「進行中 / 開放收案 / 收案中 / 招募中」優先，不被 target/enrolled 數字推論覆蓋。
3. 數字滿額只作為輔助判斷，而且只在 targetNum 與 enrolled 都是單純數字時啟用。
4. targetNum / enrolled / monthSigned / monthEnrolled 保留文字，不再強制轉數字。
5. targetNum / enrolled 編輯欄位由 number 改為 text，可輸入 3-5、0/2、需問 sponsor、prescreen 等臨床常用格式。
6. 匯入時若只是從整列文字猜到停止/結束/滿額，不會覆蓋既有手動開放狀態；若有正式 status/收案狀態欄，仍可更新。
7. 狀態下拉選單增加「開放收案、需問slot、還未SIV、預備中、試驗結束」。
